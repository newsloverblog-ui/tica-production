# Tica rebuild — Sprint 2 foundation

Started: 31 October 2026

## Implemented in this sprint

- Closed the post-checkout booking-enumeration boundary: every event completion redirect now uses a shared 24-hour signed URL, the signature covers event, booking and offline-display state, completion revalidates the booking/event relationship, and the success response is private and `no-store`. A regression scan rejects any controller that reintroduces an unsigned completion redirect.
- Removed browser authority over ticket pricing and schedule selection. Online checkout now derives `free` versus `normal`, price, stock and per-order limits from the active ticket record; a modified hidden field cannot turn a paid ticket into a free booking. Quantity shape is bounded by event type, authenticated prior admissions reduce the remaining purchase allowance, venue option arrays must exactly match the server catalogue, single-event dates are canonicalized from the event, and multi-date submissions must match an available date owned by that event.
- Rebuilds every event quote from the live catalogue immediately before review and again before payment dispatch. Ticket and variation prices, stock, early-bird eligibility, fees and coupons are re-derived from current server records; stale or malformed coupon configuration fails closed, fixed discounts cannot exceed the eligible subtotal, and a legitimate 100% discount becomes an idempotent zero-balance booking without entering a gateway. Ticket-option and cumulative purchase limits now share one authoritative service across quote review, locked inventory reservation, free/offline booking creation and late-payment stock reacquisition. Authenticated buyers are keyed by customer identity; guests are keyed by a normalized HMAC email fingerprint that is backfilled for historical guest bookings and hidden from serialization. Active holds count toward the same cap, final reservation consumption is buyer-bound, and parallel sessions or an expired payment returning after another purchase cannot exceed the organizer's current limit.
- Made payment-hold replacement atomic. The prior hold is ownership-checked by session or customer, restored, marked replaced and exchanged for the new selection under the same event/ticket locks. A failed replacement rolls back to the original valid hold, a replaced token is single-use, cross-checkout tokens fail closed, and the transient restore no longer sends a false waitlist-capacity notification.

- Added correlation IDs to every Laravel response and log context via `X-Request-ID`.
- Added baseline browser security headers: MIME sniffing protection, same-origin framing, strict referrer policy, permissions policy and a report-only Content Security Policy.
- Added production HTTPS Strict Transport Security.
- Added liveness and database-readiness endpoints at `/health/live` and `/health/ready` for uptime and deployment probes.
- Added named rate limits for authentication, checkout submission and organizer ticket scanning.
- Extended abuse controls across public contact, organizer-contact, newsletter, browser-push, advertisement-counter and both event/product coupon and checkout writes. Public payloads are bounded, newsletter registration is idempotent without exposing membership, and advertisement views increment atomically. Product reviews now require an active verified customer with a completed, non-refunded purchase, accept only bounded review fields and update one customer/product record instead of mass-assigning the request.
- Closed account and payment-callback route gaps found by a full route-table audit. Customer/organizer password changes and wishlist writes now require the correct guard, admin login and session-cart mutations are throttled, and a regression test rejects any future application browser mutation without an authenticity or abuse-control boundary. All legacy event/shop payment initiation, callback and cancellation routes now reuse the production gateway allowlist, fail with 404 when their integration lacks the durable production contract, and are rate bounded for sandbox use. The gateway regression test discovers every policy-gated route from the live route table instead of relying on a hand-maintained callback subset, so a newly added unbounded legacy endpoint fails CI automatically.
- Replaced permissive cart mutations with a bounded catalogue-aware contract. Cart item IDs and quantities are validated and capped, arrays must align, only items already in the session cart can be updated, inactive/missing products and insufficient stock fail without partial mutation, empty removal is idempotent, and order-now derives the product and accumulated quantity from validated fields rather than a client-encoded delimiter.
- Removed a duplicate customer authentication route.
- Added unit coverage for request IDs and security headers.
- Added an append-only `audit_logs` domain ledger with actor, subject, before/after state, request ID, IP, user agent and redaction of sensitive values.
- Removed the legacy public maintenance bypass URL and its plaintext database token. Maintenance changes now use structured Artisan arguments, reject invalid status/message input, check command success, clear legacy tokens and compensate back to the prior runtime state if the database save fails; the existing authenticated admin exception remains the only maintenance control path.
- Closed the remaining admin mutation permission gaps. Bulk customer deactivation, product settings, language keywords, subscriber management/email and push notifications now use their existing functional permissions. The permission middleware supports explicit any-of scopes for the shared rich-text image service, while every authenticated admin mutation is covered by a regression test that permits only named authentication/profile exceptions. Money-moving manual actions now require a second explicit finance boundary in addition to their domain permission: event-payment decisions require both `Event Bookings` and `Transaction`, while shop payment decisions and evidence-based refunds require both `Shop Management` and `Transaction`. Permission evaluation is centralized on the administrator model, malformed assigned roles fail closed, and non-finance administrators receive a truthful read-only “Pending finance review” state instead of unusable approval controls.
- Added generated 1200×630 event share cards with real event imagery, a licensed fallback, cache validators and bounded raster decoding. Public share cards, detail routes and organizer catalogues expose only published events or buyer-facing cancellation notices; suspended organizers are removed from discovery, while drafts and archived events require an authenticated owner/admin preview and are marked `noindex`.
- Removed the last admin state-changing GET action by converting support-ticket unassignment to a CSRF-protected POST form and added a regression audit for future admin GET mutations. An application-owned global middleware now blocks every vendor `/install` and `/update` route by default—including the vendor's unguarded `/update/final` endpoint—and blocks them unconditionally in production. Explicit local flags are required for installation, and release readiness fails if either web installer flag is enabled.
- Audited organizer/admin booking status changes, booking deletion, exports, ticket check-in, withdrawal requests, cancellation, approval and decline.
- Closed an organizer authorization gap in bulk booking deletion by applying organizer ownership scope to every selected record.

Only a validated `https://checkout.paystack.com` URL can be shown as a return-to-checkout action.

Webhook and fulfilment paths now require the durable intent and gateway-scoped ledger identity rather than reconstructing state from cache or a legacy reference alone.

A unique singleton key now prevents a second row, while every event/product sale, manual approval, refund and cancellation reversal acquires the same locked record through one fail-closed service. The migration seeds only a genuinely empty table and deliberately refuses to continue when historical duplicates require finance reconciliation; the production readiness command also blocks traffic if the live row is subsequently missing or malformed.

Application services may not import or write the earnings model outside the singleton service, every authoritative finance mutation must acquire that locked boundary, and the certified Paystack/Flutterwave controllers are checked against direct earnings writes. Redirects are restricted to `https://checkout.flutterwave.com`.

Connection failures, timeouts, throttling and upstream server errors now preserve the original reference and reservation as `verification_required`; definitive initialization rejection is the only initialization path that releases inventory. The browser callback no longer trusts a query-string status, provider pending/processing states remain recoverable, terminal provider failures release inventory, callbacks are throttled, and fulfilment deduplicates against the gateway-scoped ledger identity rather than the legacy transaction column.

The bounded client pages through successful provider transactions for the previous day; finance now receives encrypted reconciliation evidence for gateway-only charges, locally completed payments absent from the provider day, missing bookings, non-terminal local states, amount/currency drift and missing or mismatched gateway-scoped sale-ledger identities. Mismatches and failed runs use the shared operational incident channel, and the existing admin review screen can filter both supported gateways.
- Added an application-owned payment-gateway contract allowlist. Only Paystack and Flutterwave, whose durable intents, reservations, server verification, idempotent fulfilment and recovery are implemented in code, can be enabled for event sales; configuration can disable but cannot promote another integration. - Replaced both duplicated manual event-payment decision paths with one row-locked service. ## Deployment notes

- Keep `CSP_ENFORCE=false` initially. Review violations in staging, remove legacy inline/eval requirements, then enable enforcement.
- Point basic uptime checks at `/health/live`; use `/health/ready` for deployment/load-balancer readiness because it intentionally returns HTTP 503 when the database is unavailable.
- Confirm reverse-proxy forwarding and trusted-proxy configuration so HTTPS and client IP detection are accurate.
- Tune rate limits using staging and production traffic before high-volume on-sales.
- Run `php artisan migrate` during deployment before enabling mutation routes that write audit records.
- The earnings-singleton migration requires zero or one historical `earnings` row. If migration stops because multiple rows exist, finance must reconcile the history to exactly one authoritative total before retrying; do not automatically sum or delete rows because their provenance is not inferable from the table alone.
- Grant the application database user INSERT/SELECT—but not UPDATE/DELETE—on `audit_logs` where the hosting platform supports table-level privileges.
- Ensure Laravel's scheduler runs every minute; `payments:monitor-intents` is scheduled every five minutes.
- Set `TICKET_RESERVATION_MINUTES` to the approved checkout hold period (15 minutes by default). The payment-intent monitor also restores expired ticket holds.
